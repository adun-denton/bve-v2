## Public interfaces and persistence
- GET /api/operation-preparation and POST /api/operation-preparation resolve the exact current adopted records for the five-field product/applicability/operation/Brand query.
- POST /api/operation-request remains the original frozen request interface.
- GET /api/content-review?productId=<ID> returns scoped decisions, lineage, requests, rounds and truthful jobs.
- POST /api/candidate-action-reference prepares an authenticated human action reference for a closed candidate.decide packet.
- POST /api/candidate-decision validates/commits that packet and returns its exact decision reference/sequence.

The server and developer handler tests call the same operationUIHandler. In-process handler evidence is not HTTP/browser transport evidence. Original PNG integrity and source-bound identity validation remain separate from decisions. Combined recovery verifies decision/action/receipt chains as well as all pre-existing sources and service staging.

## Exact-action reconciliation
Both initial sending and explicit reconciliation retain the original request/decision packet, words, settings and key. A recognized typed rejection can leave uncertainty only when the authenticated server has also checked that the exact key has no receipt in its own operation scope. A failed replay of an already committed action therefore does not claim original no effect. Transport errors, unrecognized failures and unproved outcomes stay uncertain and block replacement. Successful replay retains the returned original receipt. No automatic resend occurs.

A definite rejection remains visible and still blocks replacement until the human reads the current product/content authority, reviews the displayed facts/decisions, and explicitly acknowledges. A changed head or decision tail invalidates that review and requires another read. Acknowledgment changes no server record and sends no request/decision; a fresh explicit action uses current authority and a new key. The old packet and rejection evidence remain in history. Reusing a key with different local settings refuses without overwriting the retained packet.

Operation status shows current job state plus its scoped service reports, including definite pre-start blocks. Verified partial results remain visible alongside blocked, failed and uncertain siblings. Human output approval remains separate from successful execution.
