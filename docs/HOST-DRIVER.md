# Host connection and project staff

For the 3DJAT adaptation, use the setup amendment, capability assessment and private-driver mapping below together with [INSTALL](INSTALL.md#3djat-environment-first-setup). J02 documents interfaces and authored checks only: it supplies no native driver, readiness PASS, installation or session provisioning. Ordinary upstream exploration/production staffing remains as described in [Examples A–C](EXAMPLES.md).

The installer configures a trusted private module exporting id, kind (native/fixture/unavailable) and discover(). Capability records distinguish tested/documented/unavailable and evidence for sessions, delegation, resume, userHandoff, image/originalBytes and browser presentation. Runtime readiness is not project-cycle/native verification. There is no bundled native provider and no image call on capability discovery.

The existing first SOL chat becomes the project's Conductor. Local trusted host attachment uses Kernel.bindSession(owner,{role:'conductor',tier:'SOL',sessionId,projectId:null,nonce,hostReceipt}); it creates no project or workforce. Replacement attaches to the existing projectId with replace:true, revoking the previous active Conductor. A host receipt must refer to an actual session; labels/tier declarations are not attestation.

The Conductor-side helpers in src/host-runtime.mjs use these host methods:

| Method | Actual behavior required |
|---|---|
| ensureSession({role,tier,key,previous,instructions}) | Create/resume the exact LUNA Butler or Gen session idempotently at the durable BVE key; return id, actual URL if available and stable creation receipt. Reuse previous staff rather than duplicating it. |
| configureSession({binding,access,instructions}) | Deliver only that session's private scoped envelope/instructions; have it read its actual project/job scope with host.resume. Do not infer its image/transport tools from the installer. |
| sendStatement({sessionId,statementId,projectId,roundId}) | Route the exact assignment to the bound session and record actual receipt; no authority from statement text alone. |
| notifyConductor({sessionId,eventId,roundId,checkpointId}) | Return completion to the originating/current Conductor via a demonstrated mechanism. Return sent, mechanism and evidence; a send is not consumption or generation permission. |
| Host presentation | Actually open/display the supplied durable local BVE round URL when supported. Record unsupported browser opening accurately. |

Staff creation is on demand after production activation. BVE reserves a worker slot before calling ensureSession and binds it to one job. Lost responses retain the stable key. Maximum active roster is eight; completed worker turn retirement must not invent new attempts. The driver owns any necessary actual host turn closure and preservation of external original returns. No advanced recovery/replacement scheduler is required.

Run only the assigned operation through statements. runWorker verifies the exact resumed worker/assignment, matches the adapter capability to the assigned capability and the selected executor ID, and reads/hash-checks only assigned originals before starting. Unavailable capability/route produces an attributable pre-start blocked report without consuming an invocation; the selection/history and explicit same-assignment recovery remain available. Only an unstarted assigned worker can report this block. A running or uncertain attempt cannot be recast as no effect. runWorker then starts that exact attempt once, invokes its compatible adapter, delivers original bytes with assignment token and appends its report. Butler reports readiness/presentation/outcome; deterministic services independently validate/register and commit checkpoints. Conductor's helper does not privately produce/transfer/register the worker output. Follow [Examples A–C](EXAMPLES.md).

scripts/session.mjs PRIVATE_ACCESS_FILE resume returns bounded records. call reads a private {op,key,input} packet on stdin. HTTP is normal; transport:kernel with an existing private root is available only when shared-file access is actually supported. It calls the same scoped Kernel interfaces with recover:false and never takes owner status. For an existing adopted-operation root, Kernel transport also needs its existing product/template policies: optional private runtimeOptionsFile is an absolute JSON file containing only products, templates, business, operations and existing pinned services constructor options. It supplies no credential or new authority; the exact session/assignment token is still checked. Services are accepted only for an already-v5 root; transport cannot promote a v4 root. The existing service pin validator still applies. No migration, recovery or owner option is accepted, and recover remains false. HTTP uses the configured server instead. Protect envelopes, private policy files and assignment tokens; do not paste them into public reports. Filesystem owners are trusted, not OS-sandboxed by these application boundaries.

No paid provider fallback, setup generation, assumptions of concurrency or silent one-session imitation. Actual SOL/LUNA session creation, native original return, browser opening and automatic completion in the initiating interaction must each be tested on a supporting host. returnRound records a sent/failed delivery attempt separately from the freshly read acknowledgedAt and consumedAt facts, returning event/round/checkpoint/current-recipient identity. It neither acknowledges nor consumes on the recipient's behalf. While the event remains unconsumed it supplies the supported manual action: Reopen the product's Conductor and ask it to resume the project and read unread durable events. The original round Conductor lineage remains intact when the active recipient is an explicit replacement. Host exception text is not copied into public durable evidence. Fixture callbacks establish only the authored protocol.

## Narrow private-driver mapping

The trusted private module remains `default {id, kind, discover, ensureSession, configureSession, sendStatement, notifyConductor}` using the existing call sites. There is no supervisor, new orchestrator, generic bridge or new public credential-bearing protocol. This section specifies future private implementation; no module is supplied by J02. Keep actual paths, IDs, receipts, secrets and host transcripts outside Git.

| Existing entry point | Request / reply and required checks |
|---|---|
| `discover()` | No production invocation. Return capability entries with `status` and bounded evidence references; current installer requires sessions/delegation/resume/userHandoff `tested` plus evidence for its connection status. Retain image/originalBytes/browser/wake/concurrency separately. Record evidence origin/date/limits in the private ledger; never relabel a fixture callback as native proof |
| `ensureSession({role,tier,key,previous,instructions})` | Post-activation `ensureStaff` calls this for Butler/worker with tier LUNA, a reserved stable key, optional prior `{id,url}`, and role text. Return `{id, url?: HTTPS|null, receipt}` for the exact real session. Verify actual role/model evidence privately; do not infer it from `tier`. Preserve key-to-ID/creation-receipt mapping durably before acknowledging; query/reconcile the same key on lost response. Missing identity/receipt rejects. Never make a second session after an unknown creation outcome |
| `configureSession({binding,access,instructions})` | Deliver only that real session's private BVE-issued access/nonce and exact role instructions; never owner/human/all-staff credentials. Have the session call `host.resume` using its nonce. Awaiting this method alone does not prove receipt: its return value is not independently authenticated/stored by the helper. Preserve the recipient acknowledgement privately and compare the kernel resume receipt/session/role/project/job scope |
| `sendStatement({sessionId,statementId,projectId,roundId})` | Recipient reads the exact assigned statement via scoped resume and verifies original Butler instructions. Return a bounded attributable delivery receipt. The helper returns it; it does not automatically turn it into readiness or a checkpoint. Butler's own `statement.report` ready is still required before workers; the exact worker appends its own report |
| `notifyConductor({sessionId,eventId,roundId,checkpointId})` | Reply `{sent:boolean, mechanism:string, evidence?:string|null}`. Route to the current non-revoked Conductor while preserving originating lineage; retain event identity. `returnRound` records `event.delivery` sent/failed from this reply, not human acceptance or consumption. Missing/failed return remains durable and incomplete. Record recipient acknowledgement and consumption separately |
| Browser/manual presentation | No new method name is implemented here. Use a proven host display mechanism or explicitly hand over the exact loopback durable round URL on the runtime machine. Report whether opening, visibility, review, wake and acknowledgement actually occurred separately |

Post-install access remains private `{origin,role,sessionId,projectId,token,nonce}` with either normal HTTP or explicitly verified `{transport:'kernel',root,...}`. Kernel transport requires an existing recognized root and `recover:false`; it neither takes ownership nor transports an inaccessible local root into the cloud. HTTP retains loopback Host/Origin checks. A worker's separate assignment token permits only its exact allowed source originals/delivery; the helper never grants another role's authority. Never print access envelopes in a handover packet or source log. Runtime evidence/errors use safe references rather than secret values or whole transcripts.

### Pre-install provisioning and post-install identity continuity

Before BVE exists, use the supporting host's **native** create/resume and acknowledgement mechanism directly. Do not call `ensureStaff`, `Kernel.bindSession`, the installer, `configureSession` with invented bearer material, or `host.resume` to fake pre-install readiness: these require an installed recognized BVE root/active project. The inspected host has not demonstrated the required native mechanism.

The private installer records non-secret setup lookup keys scoped by workspace UUID and role, actual session ID/link, actual model evidence, instruction hash and receipt references. Preserve a suitable existing Conductor; create/resume one Butler only under the separately authorized setup gate. These setup keys are private host bookkeeping, not new BVE APIs or execution permissions. No project round or worker exists at this stage.

After accepted installation/adoption and explicit product intent, bind that **same** Conductor through the existing trusted-owner `Kernel.bindSession` route and configure its scoped access. Reuse an existing project's UUID. Prepared 3DJAT domain/product UUID connection requires J03; current `project.activate` creates a project and request and must not be used to duplicate prepared products as a workaround. Attach existing known projects with their exact projectId; do not recreate them.

On the first BVE Butler reservation, the private driver must explicitly reconcile the prepared Butler with the reservation's stable key. With `previous` present, verify/reuse that exact identity. With `previous=null` but a verified pre-install Butler available, the owner-approved private mapping aliases the new project reservation key to that same prepared session and original creation receipt before returning; it must not create a duplicate. This private mapping behavior is a required later driver implementation/probe, not implemented by the current helpers. Refuse conflicts, cross-workspace identities or a session already active in another project/assignment. BVE binding enforces its own scopes; this specification does not waive them. Resume the same Butler on demand after readiness, rather than keeping a permanent idle workforce.

`ensureStaff` reserves before host creation and derives its binding challenge from the stable key. Do not replace that with an unrelated challenge or lose the key after a timeout. When actual native identity cannot be found after an uncertain provisioning call, stop for owner reconciliation; no blind repeat or replacement. Product-role instruction revisions and replacement must preserve old binding/history. Active Conductor replacement is explicit owner binding with existing projectId and `replace:true`, revokes the old bearer, then configures/resumes the new exact identity. No workers or attempts are recreated.

## Pre-install receipt and exception requirements

The private ledger must resolve every J01 readiness reference to actual immutable evidence: workspace UUID, source/instruction version and hash, exact session IDs (and exposed links), role/model evidence, per-recipient acknowledgement, actual resume proof, challenge and no-production return receipt, timestamp and responsible owner. A return receipt links Conductor send → Butler received/acknowledged → same challenge returned → Conductor read/acknowledged. Do not publish actual records. J01 session IDs are bounded to 200 characters; do not truncate a longer native ID to make it pass. Schema-valid authored references remain fictional.

Role files establish **definition readiness** only. Actual sessions establish a separate **session-provisioning** gate. Zero workers and zero images are invariant. The 3DJAT setup amendment prepares a supported Conductor/Butler before BVE, without changing ordinary exploration staffing or granting production authority. The seven-stage installer order is normative in [INSTALL](INSTALL.md#3djat-environment-first-setup).

No installation-dependent session-provisioning exception was demonstrated or approved by J02. Known dependencies on BVE-issued bearer/configureSession/host.resume are normal **deferred activation**, not exceptions to having real sessions first. Unsupported durable provisioning on the inspected task surface is **blocked**, not an automatic exception.

Only if a later actual host probe proves a concrete installation dependency may the installer record: exact host API/component; observed failure/evidence; alternatives checked; independent prerequisites completed; minimum post-install activation; owner; acceptance test; and explicit user/orchestration approval receipt. Until approval it is `exception-required`, never PASS. Approved exception still leaves operational readiness incomplete until the deferred real sessions/return pass. A non-generative pilot or a server that launches cannot waive this gate.

## Bounded gaps and verification limits

- No native private driver is bundled. Task-agent metadata alone supplies no demonstrated durable user-openable staff provisioner or exact model attestation. The operating-host owner must supply and verify that route; J02 provides no executable bridge.
- Pre-install setup-to-BVE Butler identity aliasing needs a private driver's durable key mapping/probe; current `ensureStaff` receives only its BVE key/previous binding. Do not silently invent that continuity. No frozen J01 type or runtime implementation is changed here.
- J03 product/workspace adoption, file mutation/recovery and independent reads remain unimplemented. No prepared UUID may be replaced with an upstream newly generated project ID.
- The inspected CLI checks for `operational` to exit zero, while current `installHost` returns `incomplete`, `fixture-verified` or `runtime-ready`. Its exit code cannot prove readiness. J12 must reconcile/document the final installation CLI status/exit policy in its own authorized scope; J02 changes neither script nor runtime.
- Authored tests reject invalid/missing readiness fields, wrong roles/tiers, duplicate IDs, nonzero setup workers/images and unapproved exception declarations. They also preserve fixture/unavailable capability classification and show that driver claims can at most yield connection status, not actual session attestation. Tests do not validate real credentials, native receipts, browser access, source atomicity, model tools, image quality, original bytes, IMG20 or P1122-COLD.
