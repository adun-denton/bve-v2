# Human workflow and review findings

## Ordinary journey

An installed host supplies Conductor and compatible executors through their narrow functions. The designer discusses the brief and requests six images once. Conductor commissions six distinct specifications. Generator dispatches within that request. Butler independently registers results and opens a board that progressively shows actual images, with remaining/failed/uncertain directions clearly labeled. No user import, registration, receipt, verification, capture or finalization action is needed.

On the board, the human can compare all images, favorite a candidate, focus it, zoom, navigate, write a whole-image note, draw a region with a source-bound comment and enter overall feedback. Drafts save automatically. **Submit review** preserves an immutable submission and generates nothing unless an explicit bounded standing iteration policy exists. **Submit and iterate** also persists the next request under established count/direction/Brand settings. No confirmation follows it. Butler prepares source context without screenshots or AI; Conductor interprets it separately and commissions the next bounded iteration.

A running app lacking native adapters clearly reports that gap and keeps requests/feedback. The authored demonstration simulates those adapters; it does not prove that a ChatGPT account can be called or notified by the installed app.

## Action count

| Step | Ordinary human action count | Purpose |
|---|---:|---|
| Discuss and request first six-image iteration | 1 request, plus normal creative discussion | Supplies existing intent; no budget-entry ceremony |
| Open delivered review link | 1, or zero when already on the board | Reveals actual results |
| Compare board | 0 | All six images together |
| Favorite an image | 1 | Creative preference |
| Open focus | 1 | Inspect/annotate |
| Add whole-image note | 1 text entry | Original human feedback |
| Draw region, enter words, add comment | 3 | A creative gesture, words and explicit annotation action |
| Close focus | 1 | Return to comparison |
| Enter overall feedback | 1 text entry | Creative direction |
| Submit and iterate | 1 | Explicit submission and bounded next intent |
| Preparation, dispatch, delivery, intake, continuation | 0 | Deterministic services and configured executors |
| Review second iteration and Submit review | Creative inspection plus 1 submission | Does not request a third iteration |

A plain overall-feedback review requires only text entry plus one submission from an already open board. Annotation/favorite/zoom/navigation are optional creative controls. The automated browser test includes an extra explicit Save draft, refresh and cold browser replacement solely to verify recovery; Save draft is not required for normal use. There are **zero extra authorization confirmations** and **zero designer technical administration steps** in either iteration. Native adapter installation is separate local integration work.

## Findings addressed during implementation

- A replayed start acknowledgement originally could resemble fresh invocation permission. Every repeated start now rejects; inspection/reconciliation retains the existing attempt instead.
- Executor uncertainty now records an observation without consuming the original-result delivery slot, so the original invocation can deliver late.
- Reviews now freeze the exact source-artifact set at submission. Late images do not retroactively become reviewed evidence.
- Draft restoration is performed before board image loading completes. Browser assertions wait for the restored state, rather than assuming visibility means hydration is complete.
- Fixture labels persist with the project after owner restart. Simulation cannot become a native integration claim through reopening.

## Remaining usability limits

The board is usable with authored fixtures on desktop and mobile. Its effectiveness for real creative work and actual tool outputs has not been judged by a human. There is no embedded chat or live notification channel. Until a host adapter is installed, new production requests wait for that explicit integration gap. The root supports multiple projects with one board page each. No arbitrary canvas, side-by-side selection mode beyond the image board, annotation shapes beyond rectangles, or automated exact-pixel editing is implemented. The board snapshot remains historical evidence; production uses only each job’s declared sources and regions. Unavailable historical originals are disclosed without blocking independent jobs.

## Deferred product questions

D01: Dedicated Level 1 visual controls (accents/contrast/type/background), Level 2 metric sliders and Level 3 structured Brand metadata remain deferred product questions. The lean V2 scope did not establish these dedicated controls as an approved requirement. Their absence is not treated as a regression in this repair.

D02: Gallery comparison fulfills the minimum comparison scope. Synchronized two-image detail/zoom is deferred until human usability evidence justifies it. No general canvas engine or legacy control workflow is introduced.

No new operator decision is required for these deferrals or the current bounded repairs. Final independent technical review precedes the later operator pilot; this does not add confirmations to ordinary authorized runtime operations.
