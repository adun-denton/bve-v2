# Historical PNG imports

## Decisions before implementation

| Boundary | Decision |
|---|---|
| Contract | Frozen asset.import.stage takes historical-import; commit takes importId/stageReceipt/sha256. Frozen operational result/failure, current head plus import-state CAS, exact typed references |
| Transfer | Local-source intake only: trusted owner explicitly maps source IDs to dedicated directories. Stage reads only a declared safe relative file under that map. No arbitrary path reader, multipart/base64 wrapper or web upload command. HTTP JSON stays 128KiB; actual source bytes stay 24MiB |
| Stage | One durable SQLite inbox record and original BLOB by hash, before PNG decoding. Captured bytes bind declared hash/length. Pending and failed imports are not artifacts |
| Commit | Verify actual bytes with existing PNG verifier, parent identity/product, authenticated scope and current state. One SQLite transaction installs artifact, typed ref/origin, association and receipt; no domain fact mutation |
| Replay | Principal/operation/key/product/import scope; canonical packet binds all metadata and declared bytes hash. Same packet returns original receipt before stale checks. A source file changed after capture does not replace staged bytes |
| Identity | Original bytes stored once by hash; product/import/artifact authority remains distinct. No derivative/thumbnail is generated or substituted |
| Origin | Imported artifacts carry typed artifact-origin and historical-import refs, with no job/iteration/attempt. Legacy produced artifacts retain their existing associations and implicit produced interpretation; do not fabricate missing 3DJAT run/result refs |
| Approval | Historical approval is an unverified assertion only; it creates no design.accept or candidate decision. A later explicit human design.accept remains separate |
| Format/rollback | Opt-in root marker version 2 plus minimal versioned SQLite import metadata; SQL tables/user_version remain unchanged. Old source refuses root version 2. Existing roots require a verified exact separate combined backup matching both current domain head and SQLite contents under the existing locks, plus explicit quiescence. Unknown import versions refuse |
| Recovery | Inbox publication, verification, artifact/receipt publication and response are distinct boundaries. Explicit same-key retry, never automatic generation. Failed/pending stage bytes remain in the private SQLite backup; no orphan cleanup/eviction |
| Export/backup | Original HTTP endpoint and bounded import portable/review queries handle imports independently of jobs. Combined backup verifies imported provenance/bytes, preserves pending states and restores separately |

The ordinary J05A path remains at 16MP/24MiB/8-bit/non-interlaced limits. The [conditional IMG20 experiment](IMG20.md) adds an explicit trusted opt-in and marker 3; it is not a release-path limit increase. 20MP/IMG20 (including all thirteen private originals), attachments, previews/remaining metadata, J05/M1/P1122-COLD, real native readiness and production setup remain later gates. No original is resized or re-encoded.

## Configuration, APIs and references

`new Kernel(runtime,{...existingOptions,imports:{sources:{sourceId:absoluteDedicatedDirectory}}})` explicitly enables imports on a new connected authored root. `serve` forwards the same trusted option. Source maps are owner configuration, never request JSON; at most 16 entries, no overlap with runtime, no path discovery. A live map is identity-bound and rejects symlink/junction/case/root replacement. Original PNGs are read only from safe relative file locations under that map. Drive input and unavailable/unmapped files return MISSING_SOURCE. No original can be downloaded from a staged or failed inbox. There is no HTTP raw/base64 upload or arbitrary local-file read API in this slice; the actual imported bytes travel from that explicit local map to SQLite and then the existing HTTP original endpoint.

For an existing root with history, take and verify a fresh separate combined backup first, stop other writers, then pass `imports:{sources,migrationBackup:absoluteBackup,confirmedQuiescent:true}`. The importer independently verifies backup completion and exact current SQLite fingerprint before recording opt-in. This is not authority to migrate an operating pilot. In tests all roots and backups are disposable. Root marker 2 identifies the import feature; database tables/user_version and file-owned contracts are unchanged. Marker 1 roots without imports retain existing behavior. Source older than this feature refuses marker 2; rollback means a separate restore of the pre-import backup using compatible pinned source, not changing the marker or dropping new records. Unknown marker/feature/metadata versions refuse. A crash during promotion can leave known opt-in metadata without any imports at marker 1; owner reconfiguration finishes promotion. A leftover promotion file is a preserved interruption requiring owner inspection, not automatic deletion.

| Entry point | Input / output |
|---|---|
| `Kernel.assetCommand(token,packet)` / POST `/api/asset-import` | Exact frozen stage/commit command; frozen result or failure, 200 / 409. Identifiable invalid inputs get typed failures; unidentifiable metadata uses bounded 400 handling |
| `Kernel.importReview(token,importId)` / GET `/api/import?id=...` | Bounded internal `bve.import-review.v1`: state, exact declaration/ref, actual stage/commit receipt payloads/refs, committed artifact/ref/origin and unverified historical-claim labels |
| `Kernel.importPortable(token,artifactId)` / GET `/api/import-portable?id=...` | Internal `bve.import-portable.v1`: typed artifact/origin, original declaration, exact original base64/hash/mediaType, unverified historical claims and freshAcceptance=false |
| GET `/api/original?id=artifactId` | Existing authorized original endpoint; exact PNG bytes, never a derivative |

Human and authenticated Conductor are the only import scopes. A bound Conductor stays within its product; stage ownership binds commit to the actual principal. Source-proposer, worker, Butler, supplied role labels, and foreign staged receipts cannot authorize a commit. Import identity resolves product for the frozen commit input, which intentionally has no productId field. Source-only product proposal access is not image-import access. Historical imports remain independently retrievable after restart even when the source mapping/files are absent. New stages still need explicitly configured available sources.

Typed payload references are logical `Operational/<kind>/<id>/<revision>.json` references backed by immutable SQLite wrappers, not a new file authority or arbitrary-record endpoint. Their SHA-256 covers exact canonical payload JSON (recursively sorted object keys, original Unicode, one trailing LF). The review query exposes payload and reference for resolution. Wrapper schema `bve.import-value.v1` supplies the existing records table's id/project metadata; it does not alter the frozen payload. Stage output points to the historical-import declaration. Commit output points to the exact artifact-ref. Receipts point to immutable `bve.import-receipt.v1` payloads binding principal, operation/key/import/product, canonical packet fingerprint and output ref. Same command with different JSON key order is identical; changed metadata, source hash, import identity or actual captured bytes cannot replace an existing import.

Staged import revision is 1; commit or durable verification failure advances its state to 2. Frozen result committedRevision reports that import-state revision. The artifact itself starts at version 1; rejection/verification failure registers no artifact. Source/hash/length assertions are compared with actual captured bytes at stage. PNG CRC/decompression/depth/interlace/pixel checks and declared-versus-measured dimensions are independently checked before artifact registration at commit. A declaration's original importedAt/source revision/locator/approval text is retained as an unverified historical assertion; verifiedAt and measured dimensions/hash/size come from the actual verifier. An ICC chunk is preserved but not interpreted or certified by this slice.

Every JSON request route now uses one bounded strict UTF-8 reader. Product/import limits remain 128KiB; legacy `/api/op` retains 34MiB and its envelope/response semantics. Fragmented Unicode is preserved, malformed/truncated encoding returns 400 before dispatch, and no BOM stripping or normalization occurs. The narrow shared-reader change also removes the old per-chunk decoding defect from the legacy route and has an explicit compatibility regression.

## Origin, interruption and backup

Imported artifact rows have origin=import and importId/importRecord, with no generation job, iteration, assignment or attempt. Frozen artifact-origin uses its import branch. Legacy produced rows and source snapshots retain their existing interpretation/fields; no synthetic run/result references are manufactured to retrofit them. Imported source snapshots include origin/import identity and remain subject to exact product/version/hash/region checks in ordinary comparison/commission paths. A new operational human design.accept is separate from imported historicalApproval and does not rewrite it. freshAcceptance=false in the import view describes the import action, even if a later separate acceptance record exists.

Stage captures bytes plus declaration/receipt atomically in SQLite before decode. Commit verifies first, then atomically installs artifact, origin/ref, association and receipt. Fault hooks distinguish before inbox, after stage, after verification, after artifact commit, before response and before portable export. Known commit followed by an acknowledgement fault returns EXPORT_PENDING with its real receipt. SQLite acknowledgement errors may return EXPORT_PENDING without evidence when publication cannot be established; inspect/retry the original key rather than inventing another ID. Prepublication IO faults retain the prior state. Failed verification is a durable failed inbox, not an approved artifact. A retry cannot replace captured bytes; correcting a bad source requires a new import identity.

Process termination can leave the existing domain/operational lock. No lock is stolen or automatically expired. After independently confirming the writer has exited and quiescence, use the accepted hash-checked recovery APIs and preserve their recovery records; then replay the original packet. Authored subprocess tests perform exactly this recovery. No generation or staff provisioning occurs on import/retry. Portable export is returned only when the complete original/provenance is available; export faults leave stored originals intact.

Combined backup remains the existing versioned scope, with all import inbox records/BLOBs in its SQLite payload and marker 2 preserved. Verification checks pending/failed captures and committed original/ref/origin/receipt links; missing/corrupt originals prevent a complete claim. Pending states remain pending after separate restore and can commit captured bytes without rereading a vanished source. No metadata-only manifest is a complete private backup. Domain dossier/proposal/decision history stays file-owned and unchanged; product access keys/intents still need the separately documented owner preservation. Source-map configuration is private owner input and is not automatically restored/discovered. The source package is not automatically copied into the domain or backup.

Bounds: 256 retained imports and 256MiB total captured import bytes, each original at most 24MiB/16MP. These bounds refuse further intake without deleting history; no cleanup service exists. No preview is generated: distinct preview identity/hash and remaining metadata/attachment integration are explicit later J05 obligations. Existing Windows filesystem/directory-flush and power-loss qualifications remain, and Linux evidence does not certify Windows.

## Verification

`node --test test/3djat-import.test.mjs test/3djat-import-integration.test.mjs` and `npm test` use authored roots/fixtures only. Tests cover channel variants, metadata/original round trips, real HTTP, principal/product/source scope, same-key payload binding, malformed/oversize images, exact 16MP and 24MiB bounds, failed/pending states, migration/refusal, explicit subprocess crash/recovery, separate backup/restore, historical claims versus later acceptance, source selection and strict Unicode across new and legacy routes. A Windows-only stage/commit/reopen/backup/restore test remains an independent exact-source verification gate.
