# J06 Products interface

Open `/products.html` in the local BVE owner browser. The visual board remains at `/`; direct `/#project=…&page=board` links still use the existing board.

The list reads the current file-owned domain head through the authenticated product reader. Counts refer to retained imported artifacts, product attachments, accepted dossier records and pending proposals. A failed current read is shown as unavailable, never as a zero or a trusted stale projection. The working product name and optional note are enough to create a code-less product. Creation does not create a request, round, job, worker, attempt or generation.

Product Information shows the base facts and governed dossier fields, including unknown, not applicable, pending and accepted states. Original proposals, corrected proposals, decisions, notes and accepted records stay in Development History. A human decision's action reference is prepared by the authenticated local Kernel and checked by the existing writer. Edit writes a linked correction, then a linked supersession; the correction remains pending for an explicit acceptance. The UI retains exact packets and keys when a response fails. Transport and acknowledgement uncertainty require explicit exact-key reconciliation. A typed receipt-free no-effect rejection retains its original words/key in history, requires a current reread and acknowledgement, then permits a fresh explicit decision. A reconciliation that establishes no effect follows the same route. A saved correction whose supersession was rejected has an explicit link action before separate acceptance; it need not be submitted again. Uncertain actions are never sent automatically.

Photos & Content uses the existing authenticated import and bounded media read routes. Previews are derivatives; no original is resized or reclassified. Missing/corrupt/policy-blocked media and inaccessible attachment sources are visible. Historical import claims remain unverified and are not fresh BVE design approvals.

Dimensions, monetary values and multi-field base proposals use typed correction controls. Units, currency/denomination, exact decimal amounts, dates, source locators and original proposals are retained. Each control has a precise accessible name.

Preparation selects retained imported input photos, resolves a bounded preview and current import identity, and calls the existing read-only operation discovery and selected-operation read. Late discovery replies cannot overwrite a newer Brand choice. Contract validity, operational compatibility, visual testing and human adoption are displayed separately. It displays source/capability blockers and identifies the generator as unassessed; there is no request, commission, staffing or provider action in this screen. The full launcher is reserved for J09 and deterministic execution for J08.

The authored API fixture exercises creation, counts, correction, supersession, acceptance, rejection, duplicate replay, historical reads, source loss and unchanged operational counters. The authored browser journeys include narrow viewport, keyboard, Persian text, long filenames, four retained authored originals, multi-field/cost correction with separate acceptance, rejected supersession recovery, an actual stale-head conflict, a committed decision with a lost reply and exact reconciliation, failed switching, adopted operation/Brand preparation, fresh browser and owner restart/file-only read. Its execution requires a supported local Chromium and the locked Playwright dependency. These source checks do not close P1122-COLD, native, Windows, memory, intended-machine, browser or human approval gates.
