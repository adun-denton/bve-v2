# J07 operation selection and execution seam

This implementation connects the existing file-owned product, dossier, attachment, business and adopted-template histories to a frozen operational selection. It does not make a template a capability. Contract validity, current operational compatibility, visual calibration and human design acceptance remain separate.

## Format and setup

`Kernel` takes explicit `products`, `templates`, optional `business`, optional `imports`, and `operations:true` options for a connected workspace. A fresh root uses marker v4 and SQLite user version 2, with the exact ordered feature list for operation selection, optionally historical import and experimental PNG20. Existing roots never auto-promote. Explicit conversion of an existing connected root requires `confirmedQuiescent:true` and `operationBackup` pointing to a verified private combined backup whose domain head, root marker and operational database fingerprint match the live root. Conversion adds an `operationSelectionFormat` row and pairs SQLite 2 with root marker 4; an interruption that leaves mismatched versions refuses reopening. Test this only in disposable roots; no live migration or rollout is authorized.

An instance without `operations:true` refuses root v4. The combined backup verifier checks the paired format, full selection rows and links. Older root versions and ordinary legacy request/round behavior retain their existing paths. A future reader that does not recognize v4 refuses its marker.

Reopening a matching experimental v4 root preserves all three features and SQLite version 2. An ordinary option refuses an experimental root without changing its marker. Promotion of an existing ordinary root to experimental requires a matching private combined backup before writing; v4 promotion retains the operation feature. This format check does not qualify 20MP image behavior.

## Narrow API

`operationDiscovery(token,{productId,applicability,branded,brandTemplateId})` reports signed adopted choices and product blockers without probing a generator. Its execution state is `not-assessed`; each candidate still requires a concrete run and source proof. `POST /api/operation-request` receives the frozen `operation.request` command packet from a current human owner. `POST /api/operation-commission` takes the matching `operation.commission` packet plus the scoped round and exact candidate specifications; it delegates to the existing Conductor round commission. `GET /api/operation-selection?requestId=...` verifies the complete internal immutable row and links, rechecks current scoped native/private read grants and signed historical proof, then returns a separate `3djat.operation-selection-view.v1` product-scoped view. The view omits the workspace-wide closure and historical permission details. Its `retainedBodySha256` names the digest of the private retained body; it is not a digest of the view. Current read revocation refuses, while historical source loss may remain a recorded blocker. `GET /api/operation-discovery` exposes the read-only discovery query. These routes add no UI workflow.

The request command validates the complete run, resolves the active per-applicability signed decision (including an earlier adopted revision after an unadopted draft), current product/dossier/attachment and optional business history, and exact imported or produced originals. The SQLite row has canonical `bodySha256`, an exact reachable file closure, historical grant fingerprint, separate Brand, original regions and parent artifact identities. An existing key and identical packet returns its verified request; a changed packet conflicts. Full bounded row and reverse-link inventory is checked at request/read/commission/attempt seams. A pending round holds `selectionRequestId` until commission so the frozen request has no premature commissioned link; that link is made atomically with iteration and jobs.

The existing `round.create`, `round.commission`, `worker.assign` and `worker.start` APIs carry selected requests. Selected specifications must preserve the run's exact sources, attachments, parent artifacts, canonical direction/Brand and output roles. Global generator allocation/start is denied for selected jobs, so only the scoped worker path can start an attempt. Current human and active Conductor grants, selected decisions, product/business authority and exact original bytes are checked at preparation, commission, assignment and once-only start. The original request snapshot remains readable after a later change, but cannot authorize a fresh effect. The regular BVE intake independently verifies returned PNG bytes and retains partial and uncertain outcomes.

Imported source proof reuses the historical inbox's stage, commit, immutable wrappers, idempotency receipts and original decoder; produced source proof follows the actual job, assignment, delivery and BLOB. A missing or changed source blocks dependent effects. A review-bound region must match its immutable submitted coordinates. `Fresh` can omit an old source; `Follow` may select a subset. A declared parent round must belong to the product and have an actual checkpoint.

Selected produced originals and parents check the retained BLOB length and shared 24MiB per-original / 144MiB aggregate budget before a bounded byte fetch. Actual verified bytes count against the same selected-source budget as imported originals.

The existing generator path commissions `generative` runs. A `deterministic` run can be retained as a request, but commission reports `CAPABILITY_UNAVAILABLE` until an actual compatible executor and corresponding frozen link shape are implemented and independently reviewed. Discovery never claims that an executor exists. Native host, intended-machine, browser, memory/recovery, Windows and IMG20 gates remain open. No user acceptance or production setup is established by authored fixtures.

## SD1 integrity repair

The historical imported-original inspector checks the prototype appropriate to each record or array before authentication or I/O. It retains selected artifact, stage, immutable and idempotency metadata for the entire call. Its final fence compares those exact rows and the owned SQLite connection's logical mutation count; it does not fetch each selected BLOB twice. The authored regression observes actual `SELECT data` calls, a coherent corrupt PNG reaching decoder refusal, a coherent semantic receipt contradiction, and the final-hook mutation counterexample. These checks do not establish kernel-wide protection from outside writers.
