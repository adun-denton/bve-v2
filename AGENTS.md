# BVE working instructions

Read README.md, docs/WHY.md, ARCHITECTURE.md and CONTRACTS.md before changing software. Current roles live in docs/roles; canonical worked scenarios live only in docs/EXAMPLES.md. Implement those concrete sequences; role labels or an installer doing every function do not prove delegation.

The project owns durable reality. One SOL Conductor, one on-demand LUNA Butler and 0–6 bounded LUNA workers are its maximum roster (8). No Generator supervisor or Foreman. Installation provisions host integration, not project staff. Before first production in an unconfirmed project context or an ambiguous project switch, Conductor checks the registry and active binding, then asks the user once to choose an existing project or confirm a new one. A brand name or “new visual exploration” is not project confirmation; an already confirmed, unambiguous continuation requires no repeated question. Exploration creates no production workforce. Generation is optional; each Conductor–Butler operational cycle records statements and an automatic checkpoint.

Use existing SQLite records, receipt/idempotency rules and narrow identity-bound APIs. Preserve original-byte integrity, human review/acceptance separation, annotations, autosave/conflict recovery, uncertain invocation boundaries and private backups. No second statement database, generic workflow engine, architecture reset, advanced recovery orchestration or new artifact-production features in this slice.

Routine bounded work proceeds under existing user intent; no repeated approval gates. No setup image calls, unrequested retries, charged-provider switches or private disclosure. Existing implemented functions with a canonical example determine the supported method. Future unsupported capabilities may be reasoned about without inventing platform requirements.

Current instructions describe the current system directly. Keep development rationale, old designs and debugging evidence in Git/review reports, not appended to role instructions. Do not copy private MSB material into public files. Preserve active/historical roots and uncommitted work; back up before authorized runtime/schema changes. Public evidence uses disposable authored fixtures; report native session/tool/byte-return/notification/browser gaps separately. Never self-accept, merge or declare stable release.
